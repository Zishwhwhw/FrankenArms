## Мой безопасный рабочий цикл

1. Записываем цель в GDD или задачу на 3–10 строк.
2. Делаем одну маленькую правку в отдельном commit/checkpoint.
3. Unity компилирует C#, затем запускаем Play Mode и читаем Console.
4. Только после проверки берём следующую задачу.
5. В конце сессии обновляем `SESSION_HANDOFF.md`.

## Выбери варианты (пришли номера)

### 1. Версия Unity и графика

- **1A (советую):** Unity LTS + URP — универсально для 2D/3D, меньше риска для первого проекта.
- **1B:** Unity LTS + Built-in — только если старый проект уже на нём и миграция принесёт риск.
- **1C:** Unity LTS + HDRP — для графически тяжёлого 3D на мощном ПК.

### 2. Как AI работает с проектом

- **2A (советую начать):** Я работаю через файлы и Git, а Unity CLI компилирует/запускает проверки. Надёжный минимум, без стороннего bridge.
- **2B:** 2A + Unity MCP/bridge — агент сможет запрашивать состояние сцены и Console. Подключаем после того, как Unity откроет проект.
- **2C:** Встроенный Unity AI Assistant — отдельный продукт Unity; зависит от доступности, аккаунта и тарифа.

### 3. Редактор кода

- **3A (советую):** Visual Studio Code + C# — лёгкий и бесплатный.
- **3B:** JetBrains Rider — сильная поддержка Unity, но нужна лицензия или подходящая версия.
- **3C:** Cursor — AI-редактор, удобен для подсказок, но не заменяет Git и тестирование.

### 4. Контроль версий

- **4A (советую):** Git + Git LFS для больших ассетов (PSD, FBX, WAV, большие PNG и т. п.).
- **4B:** Git без LFS — только для маленького прототипа без тяжёлых бинарных файлов.

### 5. Порядок разработки

- **5A (советую):** Вертикальный срез: один герой → одна комната → бой → победа/поражение → сохранение.
- **5B:** Сначала полностью документ/GDD, потом прототип.
- **5C:** Сначала повторить старый проект как мини-референс, затем заменить механики по новому GDD.

## Unity CLI: что нужно подключить

На 2026-11-11 Unity Editor и Unity Hub не обнаружены на этом Mac, поэтому команды Unity сейчас неоткуда запускать.

После установки Unity Hub и Editor я подключу путь к `Unity.app/Contents/MacOS/Unity` и проверю команды:

```sh
Unity -batchmode -quit -projectPath "$PROJECT_PATH" -logFile -
Unity -batchmode -quit -projectPath "$PROJECT_PATH" -executeMethod BuildScript.BuildMac -logFile -
```

Первую команду используем как тест компиляции; вторую добавим только после появления сборочного скрипта. Не запускать команды с `-quit` при открытом в том же проекте редакторе.
